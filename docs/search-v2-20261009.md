## Query and API

`GET /api/search?q=Agent&type=all&page=2&pageSize=20&sort=relevance`

`lib/search.ts` defines the shared contract and validates trimmed keywords (120 UTF-16 units),
type/sort enums, positive integer pages and page sizes (1–50, default 20).
Invalid parameters return 400; database failures return 500 without pretending the result set is empty.
The previous `limit` parameter remains an alias for `pageSize`.

`lib/db-search.ts` uses one parameterized SQL statement:

1. `UNION ALL` normalizes published posts, skills and gallery images. Posts search title,
   excerpt, content and tags; skills also search Chinese summary and content; gallery searches
   title, public description, category and tags. Draft posts never enter the candidate set.
2. A materialized matched CTE scores the strongest matching field, rather than adding weights:
   exact title 100, title prefix 80, title substring 60, exact tag 50, summary/description/category
   substring 25, body or partial tag 10. This guarantees that a title match outranks body-only matches.
3. Category filtering occurs before database pagination. Relevance order is score descending,
   creation time descending (nulls last), type and unique ID ascending. Newest order drops score.
4. Global counts and the selected page are aggregated in the same statement/snapshot. Empty or
   out-of-range pages retain accurate totals. Only display fields return; excerpts are bounded to
   1,000 characters, and full bodies and internal scores never return.

`%`, `_` and backslashes are escaped before `ILIKE`; input remains SQL parameters. Sorting uses
a fixed CASE expression, never interpolated SQL. A stable tie-breaker prevents duplicates within
an unchanged dataset; concurrent publication/deletion between separate page requests can still
shift OFFSET pages.

## UI and compatibility

SearchClient retains the original visual layout, local history (ten items), highlights and empty
recommendations. URL `q/type/page/sort` drives queries and browser history; keyword/category/sort
changes reset the page. Input is debounced 350ms. AbortController plus request identity and effect
cleanup prevent stale responses; a 15-second timeout has separate error/retry feedback. React text
nodes and marks replace HTML injection for highlights. Tabs scroll horizontally and titles wrap.

Automatic 350ms input updates use `router.replace`; Enter, history/suggestion selection, category,
sort and page controls retain `router.push`. History entries are keyboard-focusable buttons, and
moving focus within the search/history area keeps the dropdown open. Clearing the input opens
history without requiring a blur/refocus cycle.

Recommendations load only when global counts are zero, via `/api/posts/public?limit=4`. The existing
unbounded public metadata response stays compatible for other callers. The blog's current-page
filter is explicitly labelled and links to global search; PR #12 tags and pagination remain intact.
