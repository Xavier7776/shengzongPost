# Edition v2 evidence and correction contract

The validator accepts explicit versions 1 and 2. Version 1 retains its original fields, text serialization, citation URLs and fingerprint; extra v2-like fields never upgrade its chart labels. Version 2 is an opt-in contract for reviewed content, not a migration of old editions. The existing metadata-only manual generator still emits v1 teaching charts. No model key, cron, publishing channel or schema migration changes here.

## Reviewed evidence

V2 sources add authors, organization, pinned version, checkedAt, verification, researchQuestion, method, experimentalData and limitations. arXiv links must include a numeric version; GitHub release tags must match the declared version. Publication dates retain the seven-day edition window; review timestamps cannot precede publication or lie in the future. Failed/unperformed metadata checks use `pending_review`, with unknown fields explicitly described as unverified, not invented. Such sources cannot support author-report or reproduction claims.

Edition-wide evidence covers the lead, takeaways and guidance. Every cited narrative/diagram/quiz block and secondary update requires an evidenceType and claimSourceRefs with an existing sourceId and a concrete evidenceLocation. Types are `paper_report`, `release_report`, `teaching_example`, and `site_reproduction`; source kind must agree with author/release reports. Code retains the explicit unexecuted teaching label. Source URLs retain the primary-source whitelist and escaped React rendering.

Chart v2 replaces `illustrative` with dataOrigin (`illustrative`, `paper`, `reproduced`). Each point has a value, unique label, claimSourceRefs and confidenceInterval (numeric bounds or null for unreported). The chart also declares xAxis, yAxis, unit and experiment: sampleSize, metricDirection, baseline, conditions, randomSeed (null means unreported). A null interval/seed is shown as unreported, never fabricated. Current bars support finite nonnegative values up to 1,000,000; other plot domains require a reviewed renderer change. Setting `illustrative:false` alone is rejected.

Reproduction declarations require a GitHub result artifact pinned to a full commit, run timestamp and protocol. The publisher/revision service makes bounded, nonredirecting GET checks of whitelisted source/artifact URLs before a new write. These checks establish reachability; metadata review is a human assertion, and structural validation does not independently verify a scientific claim, artifact contents or local execution. Ten historical claim spot checks are in [the audit](learn-evidence-audit-20261010.md).

## Reporting and applying corrections

Every public Blog article offers a mailto correction entry with its slug, paragraph/value, issue, original evidence and proposed change. Clicking it prepares a message in the reader's email client; the site does not claim receipt or send a message automatically. The recipient is the existing contact address. Reporters must avoid private data.

Authenticated administrators can GET `/api/admin/learn/{slug}` to obtain the structured edition and current fingerprint. A reviewed PATCH takes `{edition, previousFingerprint}`. The edition must be complete v2; keep date, topic and slug, retain all earlier revisions, and append one revision with sequential number, correctedAt, meaningful summary and previousFingerprint. Do not use this API without authority to modify the target data. Production corrections retain the execution plan's separate data-write approval boundary.

The service freezes input, validates references and source reachability, locks the existing pair, and compare-and-swaps JSON plus posts title/excerpt/content in one statement. An independent readback verifies both representations before cache invalidation/public verification. The body serialization is deterministic after PostgreSQL JSON key reordering. Concurrent or stale corrections return conflict instead of overwriting. A repeated identical correction is read-only. Withdrawal/republishing, covers and attachments remain available through ordinary administration; ordinary content/title/excerpt/tags/slug edits of edition-owned posts return 409. Rejected approval leaves the submitted request pending.

Readback failure after a confirmed write reports `committed:true`; a zero-row result with unavailable readback reports `committed:null` (unknown). Reread before retrying. A transport retry can return zero after a lost acknowledgement; an independent matching readback recognizes the applied correction and invalidates caches, without another content update. Cache failure/public_pending does not justify rewriting content. HTTP 409 is a version conflict, 422 an unreachable source/artifact, and 503 a failed independent readback. The existing create-only publisher never becomes an overwrite path. Revision notes retain a previous fingerprint and explanation, not a full document archive; full point-in-time recovery remains the M11 backup scope.

Review layout in the local production artifact before enabling new v2 content. Historical production data remains v1. Rollback code preserves data; after a real v2 publication, a v1-only deployment uses the indexed text fallback and cannot be claimed to preserve v2 interactive charts. No downgrade or automatic rewrite is allowed.
