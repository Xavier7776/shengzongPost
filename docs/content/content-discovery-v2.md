# M08 内容发现与作品集联动

从已有公开内容建立三条手工策展路线：Agent 架构与治理、RAG 与长期记忆、模型架构与工程，每条串联基础、架构、实践和评估。编辑者修改 `lib/content-discovery.ts` 的策展表，或使用已有 `系列：<标题>` 标签；不新增数据库结构、模型请求或个人历史读取。

相关推荐按同系列、共同非泛化标签、相近主题和最近更新时间排序，最多五条；去除自身、草稿、重复和非法 Slug。系列失配时回退到近期公开内容，数据库失败隐藏辅助模块并保留主阅读内容。所有显示文本由 React 转义。小规模全量公开元数据缓存 60 秒，增长后需要先测量再缩为 SQL 候选集。直接 SQL 写入没有主动缓存通知，仍有最长约 60 秒的发现缓存延迟。

Mnemo、Mindstack 的项目页提供相关技术文章，策展文章提供当前启用项目的反向入口。路线明确是个人阅读建议，实践和评估需要自行验证；项目实际 Benchmarks 和实现进度以项目正文及证据为准，未新增或宣称项目实验结果。

上一篇/下一篇以 `(created_at,id)` 定序，在一条 PostgreSQL 查询内取相邻公开记录；同时间按 ID 稳定区分，旧文补录不会改变发布时间语义，无首尾回绕。保留旧调用结构和主阅读器。真实发布时间缺失的记录不产生相邻链接，数据质量由 M11 核对。

所有文章与项目提交后复用 `published-content` 失效，涵盖 Blog、Learn、Work 及分发入口。作品集页虽然原有缓存为一小时，文章撤回也会使其中的推荐失效。失效异常只返回 `X-Content-Cache-Status: failed`，不会把已提交写入报成失败而诱发重复操作。
