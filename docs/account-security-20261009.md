# 身份接口安全治理：迁移 055

## 变更概要
- 登录、注册、找回密码的发码与校验、登录后的密码修改都使用 **Neon 数据库跨实例限流**，而非旧 `lib/rate-limit.ts` 的单实例 Map。
- IP 和目标账号分别计数，匿名接口不会存储原始 IP、Email 或真实用户名；使用 `NEXTAUTH_SECRET` 或专用 `AUTH_RATE_LIMIT_SECRET` 衍生 64 位十六进制 HMAC 哈希。
- 账号找回验证码从原先“全局查匹配数字”改为绑定电子邮箱；已登录改密从原先“全局查匹配数字”改为绑定当前登录用户 ID。
- 所有新设密码（注册、改密、找回）须为 12–72 字符且 UTF-8 不超过 72 字节的口令，允许中文与空格，不引入强制混合字符规则；原有已注册密码不强制重置。
- 维护目录 `supabase/migrations/055_auth_rate_limits.sql` 增加 `auth_rate_limits` 表和清理索引。目标限流范围：单账号注册每小时 3 次、登录 15 分钟 12 次、找回发码每小时 3 次、验证码校验 30 分钟 8 次；IP 也有独立限制。
- Neon 依赖故障时重要认证接口会失败关闭；需要监控 `503`、`429` 与日志，避免把数据库故障误报成用户密码错误。

## 上线先决条件
1. 必须先完成正式 Neon 生产分支迁移 055。已在临时分支上验证，但**不自动应用生产**，需要用户单独批准。否则上线新代码会让登录与密码找回失败。
2. Vercel 已存在 `NEXTAUTH_SECRET`，可选择另设 32+ 字符的 `AUTH_RATE_LIMIT_SECRET`，以便独立轮换，不要把任何明文密钥写到 Git。
3. 在 Preview 环境先检验 `npm ci`、typecheck、lint、Vitest、Next build 及实际注册/找回流程。
4. 若使用多个 Vercel 实例，验证限流桶计数共享；账号重置十分钟后过期且成功使用后立即失效。
5. 安排数据库定期清理：`DELETE FROM auth_rate_limits WHERE window_started_at < NOW() - INTERVAL '7 days'`，在审核后单独配置任务，避免无限积累老桶。
6. 当前限流主要针对密码凭据/验证码；未来可叠加 Vercel WAF 和基于异常行为的自动封禁。验证码仍是六位，强限流是必要前提。

## bcrypt UTF-8 字节边界
使用 bcryptjs（72-byte limit）。后端对新密码额外强制 UTF-8 72 字节上限，不允许超长口令被 bcrypt 静默截断导致不同尾部同一 hash；已存在旧密码沿原有验证路径使用，不会强制旧用户修改。
