# M10-B1 积分、奖励与购买一致性

基线 `d939025322f00b1ebf0d685402c35b2cb525d3d9`，Windows 工作树 `shengzongPost-m10b`，分支 `codex/security-consistency-v3`。本轮不改表、不修历史余额、不重放生产奖励。

## 写入契约

- 购买头像框/光标：锁当前用户行，然后在同一事务判断现有所有权/已付流水、检查真实余额、扣费、发放所有权和记账。余额不足拒绝；不使用截断至零来掩盖欠款。重复购买返回当前余额。已有付费流水却缺所有权的旧记录，在本人再次购买时补发所有权而不扣第二次；已有所有权直接返回，不擅自补历史流水。
- 收藏/点赞：保留 toggle 和 like/dislike 切换语义；一次请求仍代表一次切换，不宣称 toggle 本身重试幂等。每账号/文章最多一次奖励和一次扣回；奖励已花掉时记真实扣回额 0，阻止之后继续扣回。状态、余额和流水在同一事务回滚。
- 阅读：公开文章首次读标记、2 分奖励及流水原子写入。旧读标记不补奖；已有奖励流水不重复奖励。不存在/未发布文章无法发奖。独立浏览计数仅增加公开文章，不属于积分事务。
- 评论批准：状态、5 分和流水原子写入，保留每账号/文章一次奖励的原规则。已批准的历史评论不会因重新批准而补奖；拒绝后再批准也不重复奖励。未发布/不存在文章的评论可以审核但不发积分；不存在评论返回 404。
- 研究：新页面发送 UUID v4 `requestId`；服务端用签名账号绑定流水引用，同编号重试不再扣费，返回当前余额。扣费与账本一起提交，流水失败则全部回滚。页面在丢失响应时保留编号，并用 ref 阻止重复点击。旧缓存页面无请求体仍可扣费，但每次生成新编号，不能提供跨请求幂等保证。研究后端启动/报告保存与扣费仍是不同系统，本轮没有建立整个研究运行的原子交付或自动退款机制。
- 通用积分扣回记录真实余额差额，流水失败不再被吞掉。无引用流水以 NULL-safe 比较查询。
- 收藏列表隐藏撤回文章，避免旧收藏泄漏草稿元数据。

使用已安装 Neon 的非交互 `sql.transaction(tx => [...])` 原始惰性查询。首句 `SELECT ... FOR UPDATE` 将同一账户串行化；后续 Read Committed 语句在获得锁之后读取最新提交状态。这里不经过 `_core` 单查询网络重试包装，避免网络确认丢失后自动重发已提交的扣费。不同账户互不争用该行；不存在的用户不创建积分记录。所有商品与引用参数均为绑定值。
