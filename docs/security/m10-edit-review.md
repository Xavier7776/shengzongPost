## 最小写入契约

- 提交编辑只能指向签名账号本人仍公开的文章；新稿仍使用现有 `__new__:` 前缀。请求体不能指定写入账号。类型错误、危险封面 URL、非法替换 ID 在写入前返回 400。保留已有持久化投稿限流。
- `from_id` 是被拒申请的编号：在同一 SQL 事务删除本人被拒申请并创建替换申请。本人待审/已批申请、他人申请、不存在的申请或不可编辑的文章返回 409；插入失败保留旧申请。保留现有替换语义，不宣称永久保留被拒正文的审计历史。
- 管理员批准时先锁申请，再以 pending 状态和完整原始字段快照比较。竞争者、被替换的正文或已处理申请返回 409。文章更改/新草稿创建与申请状态、备注、审核时间在同一事务提交，最后一项失败则全部回滚。
- 旧编辑申请也必须仍属于文章作者且文章公开，避免绕过新提交校验。撤回或换作者后不能批准，但可拒绝。新稿归属提交者，保持 `published=false`，批准不直接公开；重复 Slug 返回 409，申请保持 pending。
- 正文复用现有 sanitizer；保留文章封面与公开状态。精读文章复用 M05 受保护表示一致性校验，内容漂移返回 409，申请保持 pending。
- 仅当事务成功返回公开文章时清除公共缓存。新草稿、拒绝和失败不清缓存；缓存失败的既有降级契约保留。

使用已安装 Neon 原始非交互 `sql.transaction(tx => [...])`，不经过 `_core` 网络重试。第一句行锁之后，第二句 Read Committed 查询观察最新申请状态。网络确认丢失不能声称返回成功；管理员重试会看到已处理冲突，用户可以通过申请列表回读，而不会再创建文章或二次批准。
